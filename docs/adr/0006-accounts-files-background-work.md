# ADR-0006: Local accounts, file storage and background work

- **Status:** Accepted
- **Date:** 2026-11-08

## Context
Sprint 3 adds real sign-in, people administration, profile pictures and licence copies. Until the backend is chosen (Plan A: Microsoft sign-in; Plan B: Supabase Auth), the app needs local accounts that behave like the production ones. Storage calls must not freeze the screen.

## Decision
1. **`AuthProvider` port.** Passwords never live in user records. The local adapter stores **Argon2id** hashes (OWASP settings: 19 MiB, 2 iterations) in its own `local_credentials` table, re-hashes old settings on the next successful sign-in, and does equal work for unknown usernames so response times do not reveal which usernames exist.
2. **Lockout stored with the credential** (rules catalogue P4): 5 free attempts, then 1, 2, 4 … minutes up to 30, surviving restarts; an administrator can unlock. Wrong-password and unknown-user messages are identical; "deactivated" is only revealed to someone who knows the password.
3. **Temporary passwords** are generated by the app (three readable groups, no look-alike characters), shown to the administrator once, and must be replaced at first sign-in. After that, a profile picture is required before the app opens.
4. **`FileStore` port with content-addressed storage.** Files are stored under their SHA-256 hash (`<hash>.png|jpeg|pdf`), so retried uploads never duplicate. File type is decided by the file's signature, not its name. Pictures are cropped to a 512 px square PNG before storing.
5. **Sites are locations.** A site (store, mine site, workshop, office) is the `LocationId` used by the stock ledger; a site holding stock cannot be removed.
6. **Background task queue.** Every storage call from the UI runs on a single worker thread, in order, with results delivered back on the UI thread. One worker keeps storage calls from overlapping; SQLite connections are pooled with the same-thread check relaxed accordingly.
7. **Avatars are circle-cropped by the image provider**, not by a GPU effect, so they render identically on every machine (including CI's software renderer).
8. **Toasts moved to the bottom-right** (changed from Sprint 2's top-right) because page actions such as *Add person* sit top-right and must never be covered.

## Consequences
- Plan A and Plan B each need an `AuthProvider` and a `FileStore` adapter in Sprint 10; the screens and application layer stay unchanged.
- Sign-in is deliberately slow (~50 ms of hashing), which is acceptable for people and costly for password guessing.
- Long-running storage work never blocks the UI, but tests must wait for the queue (`TaskQueue.wait_until_idle`).

## Alternatives considered
- **Passwords in the users table:** simpler, but mixes secrets into data that is shown, exported and backed up widely.
- **PBKDF2 (V1.2.3):** acceptable but weaker against GPU attacks than Argon2id.
- **In-memory lockout (V1.2.3):** forgotten on restart, so an attacker could restart-and-retry.
- **Files inside the database as base64 (V1.2.3):** bloats every query and backup.
