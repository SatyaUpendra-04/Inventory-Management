# ADR-0003: UUIDv7 identifiers, UTC time, append-only history

- **Status:** Accepted
- **Date:** 2026-11-08

## Context
Records will be created offline and merged later, stored in different backends, and audited. V1.2.3 used auto-increment integers, local-date shortcuts and mutable counters (e.g. battery cycles that servicing reset to zero).

## Decision
- **IDs:** UUIDv7, generated by the client (`uuid.uuid7()`, Python 3.14+, or a small helper on 3.13). Humans see a separate asset tag or code.
- **Time:** every timestamp stored in UTC, ISO 8601 with `Z`; converted to local time only for display. All "now" calls go through the `Clock` port so tests can freeze time. Ruff rule `DTZ` blocks naive datetimes.
- **History:** usage (hours, cycles, landings) and stock movements are append-only ledgers. Totals are calculated from entries; corrections are reversal entries, never edits.
- **Concurrency:** every mutable record carries a version; stale writes raise `ConflictError`.

## Consequences
- Offline creation and replay cannot collide on IDs.
- Every meter reading and stock level can be explained entry by entry.
- Reading a total requires summing entries; adapters may cache totals, but the ledger stays the source of truth.

## Alternatives considered
- **Auto-increment integers:** collide when records are created offline on several machines.
- **Mutable counters:** simpler, but lose history and allowed the V1.2.3 battery-reset bug.
