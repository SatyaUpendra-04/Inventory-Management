# V1.2.3 Business Rules Catalogue

Business rules found in V1.2.3 (`core/service.py`, `core/security.py`, `core/auth.py`, `core/database.py`), recorded as a **reference** for the new build. Each rule is marked:

- **Keep:** carried over as is
- **Change:** carried over with the change noted
- **Drop:** not carried over (reason given)

---

## Users & accounts

| # | V1.2.3 rule | Decision |
|---|---|---|
| U1 | Roles are `admin`, `pilot`, `operator` | **Change:** Admin (Manager/Admin), Pilot, Surveyor |
| U2 | Employee ID, email and contact phone are required | **Keep:** plus profile picture required |
| U3 | Employee ID: letters, digits, `-`, `_`; stored upper-case | **Change:** V1.2.3 checks 2–20 characters but its error says 3–20. Use **3–20** consistently |
| U4 | Email: one `@`, no spaces, domain contains a dot; stored lower-case | **Keep:** unique |
| U5 | Phone: 7–15 digits, optional leading `+` | **Keep** |
| U6 | Username stored lower-case and unique | **Keep** (local and Supabase accounts; Plan A uses Microsoft identity) |
| U7 | DGCA licence number is a free-text optional field | **Change:** mandatory for Pilots, with expiry date; optional for others |
| U8 | Cannot demote, deactivate or delete the last active admin | **Keep:** more than one admin allowed |
| U9 | Cannot delete a user with active checkouts | **Keep:** applies to any custody |
| U10 | Soft delete with restore; restore blocked if username is now taken | **Keep** |
| U11 | Admin-set or reset password forces a change at next login | **Keep** |
| U12 | Users can only change their own password; non-admins cannot change their own role, status or username | **Keep** |
| U13 | First-run creates the first admin, with hard-coded default employee ID, email and phone | **Change:** first-run asks for real values; no defaults |
| U14 | `total_flight_hours` column on the user, updated on check-in | **Drop:** derive from the sortie ledger |

## Passwords & login (local and Plan B accounts)

| # | V1.2.3 rule | Decision |
|---|---|---|
| P1 | 12–128 characters; upper, lower, digit and special character; not one repeated character; must not contain the username | **Keep** |
| P2 | All unmet requirements listed in one message | **Keep** |
| P3 | PBKDF2-SHA256, 100,000 iterations, random salt | **Change (done, Sprint 3):** Argon2id for local accounts; providers handle hashing in production |
| P4 | 5 failures → 20-second lockout, held in memory | **Change (done, Sprint 3):** stored with the credential; 1, 2, 4 … 30 minutes; admin unlock |
| P5 | Login success and failure written to the audit log | **Keep** |

## Permissions

| # | V1.2.3 rule | Decision |
|---|---|---|
| R1 | Permission codes: asset view/create/edit/retire, project view/manage, location view/manage, checkout create, checkin receive, maintenance record, user manage, view contact details, audit view | **Change:** extend for reservations, approvals, stock, defects, work orders, return-to-service |
| R2 | Admin has all permissions; pilot and operator have identical view + checkout/checkin rights | **Change:** separate Pilot (drone equipment) and Surveyor (survey equipment) rights |
| R3 | Many list methods skip the permission check when no user context is passed | **Drop:** every call requires an authenticated context |
| R4 | Contact details visible only with `user.view_contact` | **Keep** |

## Assets

| # | V1.2.3 rule | Decision |
|---|---|---|
| A1 | Separate drone and DGPS tables | **Drop:** one equipment catalogue with three tracking modes |
| A2 | Serial number unique among active assets | **Keep:** per item type, and asset tags unique overall |
| A3 | One `status` field: Available / In-Field / Maintenance / Calibration Due / Decommissioned | **Change:** split into serviceability and custody state machines |
| A4 | Cannot retire an asset that is in the field or in an active checkout | **Keep** |
| A5 | Kit is a free-text name on the asset | **Change:** kits and kit templates are entities |

## Checkout & check-in

| # | V1.2.3 rule | Decision |
|---|---|---|
| C1 | At least one item per checkout | **Keep** |
| C2 | Project must exist, not be deleted, and be Planned or Active | **Keep** |
| C3 | Crew member must exist, be active, and have role pilot or admin | **Change:** Pilots for drone equipment, Surveyors for survey equipment, valid licence where required |
| C4 | Every asset must be Available at checkout; the status change is conditional, so two people cannot take the same item | **Keep:** expressed as version checks and state-machine guards |
| C5 | A return can only happen once | **Keep:** idempotent command IDs |
| C6 | Check-in records hours and cycles per item and return condition | **Keep:** usage goes to the ledger, per sortie where possible |
| C7 | Pilot hours added to a flight log with source checkin / opening_balance / adjustment | **Keep:** as sortie ledger entries |

## Maintenance & alerts

| # | V1.2.3 rule | Decision |
|---|---|---|
| M1 | Drone service due when hours since last service ≥ service interval (default 50 h); auto-moved to Maintenance | **Change:** maintenance programme tasks by hours, cycles or calendar, whichever first |
| M2 | Warning at 85% of the service interval | **Keep:** configurable threshold |
| M3 | Battery health = 100 − (cycles ÷ max cycles × 35); maintenance at max cycles (default 200) or health < 70% | **Change:** health from measured data where available; formula only as a fallback |
| M4 | **Servicing a battery resets its cycles to 0 and health to 100%** | **Drop:** bug. Servicing never resets cycles or health |
| M5 | DGPS calibration valid 365 days from service; expired calibration sets "Calibration Due" | **Change:** validity from the certificate; expired calibration blocks deployment |
| M6 | DGPS warning when calibration expires within 30 days | **Keep:** configurable |
| M7 | Damaged / Needs Inspection condition raises an alert | **Change:** becomes a defect report |
